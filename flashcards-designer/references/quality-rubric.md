# Quality Rubric

Apply to every card before presenting it. Cut or rewrite what fails.

## Worth recalling

- Victor needs it often, forgets it, or must retrieve it quickly (on call, in review, mid-conversation).
- It is not trivially searchable and rarely needed.
- It builds on understanding, not on a phrase to memorize.

## Question

- Tests one fact, distinction, or decision.
- Has one defensible answer. If two readings are plausible, add the context that removes the ambiguity.
- Avoids yes/no. Rewrite as "what," "why," "when," or "which."
- Prefer "why" and "when" for understanding, and a short scenario when judgment is involved ("A read returns stale data after a write at W=1, R=1, N=3. What changed?").
- Stands alone. Does not say "according to the doc" or depend on a neighboring card.
- Does not give away the answer in its wording.

## Answer

- Short enough to self-grade at a glance: usually one sentence, a short list, or a formula.
- Contains no second question. If it needs "and also," split the card.
- Matches the source. If the source does not support it, flag it on the card and in the batch summary rather than asserting it.
- States the condition under which it holds when that matters.

## Source

- Points at the narrowest section that supports the answer.
- File-backed whenever possible. Use `pasted:` only when no saved copy exists.

## Deck level

- No two cards ask the same thing. Merge or retire duplicates.
- Related cards are grouped in one file.
- Prefer fewer, sharper cards. A batch of 50 should be mostly keepers.

## Common failures

| Failure | Fix |
| --- | --- |
| "What is X?" for a long definition | Ask for the distinguishing property or the use case |
| List of 8 items as the answer | Split by item, or ask for the top 2 and when each applies |
| Yes/no question | Ask what, why, or when |
| Answer repeats the question | Ask something the answer adds to |
| Requires reading the doc to interpret | Add the context to the question |
